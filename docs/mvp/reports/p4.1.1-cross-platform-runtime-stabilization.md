## 3. Event trace comparison

Format: `sequence_number simulation_time handler_id event_type
source_entity_id target_entity_id health_before health_after
entity_state`. No pointer addresses, no wall-clock time, no
unordered-container iteration order. The trace is built from
the existing handler log lines (Attack, ApplyDiscreteEffect,
Death, Removal) and a small printf helper that emits the
canonical key per dispatch.

### First diff in the trace (Ubuntu vs macOS pre-fix)

```text
seq  t          handler                  event            src  tgt  hp_before  hp_after
1   13.28976    game.attack              AttackEvent      0    2    25         25
2   13.28976    game.apply_discrete_effect ApplyDiscreteEffectEvent  0  2  25  <diff>  <-- <<<<< first diff
```

`health_after` here is the per-hit damage. Ubuntu: `19`
(25-6). macOS pre-fix: `24` (25-1). Both demos proceed from this
first diff.

### Root cause

Two compounding sources of non-determinism, both fixable at
runtime (no converter or data change):

1. **`nyan::Set` is backed by `std::unordered_set`** (see
   `nyan-external/source/nyan/value/container_types.h:13`). Its
   iteration order is platform-dependent (libc++ vs libstdc++ hash
   + seed differences). The `Attack::get_damage()` helper picks
   "the first decrease effect" from a per-armour-class set that
   includes a `AoE2AttackFallback` with the conservative
   `change_value.amount=1`. The first effect taken from the
   unordered set is hash-dependent.

2. **`Event::operator<` compared only `time`** (see
   `libopenage/event/event.cpp:55` before this spike). Two
   events with the same time were treated as equal, which
   violates strict weak ordering and left the EventQueue's
   internal container order to decide dispatch sequence. The
   EventQueue uses a `std::priority_queue` over `Event`, which
   again depends on the heap's sift-up sequence — itself a
   function of how the comparator reports equivalence.

   This is a latent bug. It does not always change the dispatch
   order on a single run (if all same-time events happen to
   land in the right order on the chosen STL), but it is a
   correctness bug per `std::sort` / priority-queue requirements
   and a platform-divergence vector. The spec calls this out
   directly: "EventLoop comparator 是否满足 strict weak ordering".

## 4. Stable ordering rule

### Event comparator

The new `Event::operator<` (see `libopenage/event/event.cpp`
post-spike) is a total order over the canonical 4-tuple
`(time, handler_id, entity_fqon, creation_seq)`:

```text
1. time dominates. Earlier time → earlier dispatch.
2. handler_id (canonical name, never empty). String < for
   cross-platform determinism (glibc/locale-independent).
3. entity_fqon (may be empty for handler-level events;
   canonical idstr from the EventEntity if locked). String <.
4. creation_seq: per-process monotonic counter assigned at
   construction via std::atomic<uint64_t>::fetch_add(1). This
   is the final tie-breaker and is independent of pointer
   address or hash randomization.
```

The comparator never returns `true` for both `a<b` and `b<a`.
Equivalent events (matching on all four keys) are allowed to
compare equal -- that is the spec-allowed equivalence class.

### nyan Set iteration

`libopenage/gamestate/component/api/attack.cpp` now uses a
new helper `stable_object_fqons(set_t)` that returns the FQONs
of the contained `ObjectValue` entries sorted ascending. The
`visit_first_decrease_effect` function calls it on the outer
batch set AND the inner effect set, then walks the sorted
vectors.

The function additionally skips two effect classes that the
`Ubuntu` baseline iteration also happened to skip (but for
unordered reasons):

* `AoE2AttackFallback` -- identifiable by FQON suffix or
  prefix; the conservative `change_value.amount=1` default
  the de2_base converter writes so that *any* attacker can
  deal at least 1 damage. Picking this as the primary effect
  reads the wrong answer for the per-hit damage.
* `change_value.amount == 0` placeholders (e.g. `Ram` vs
  villagers, `AnimalPredator` vs villagers). These would
  silently swallow the attack if picked.

The de2_base nyan file convention is the source of both
filters: the converter emits the fallback as a sibling in the
same `EffectBatch.effects` set, and writes zero-amount entries
for attacker-types that deal no damage to this defender. The
filters are documented in `attack.cpp` and the report
characterizes them as "the platform-independent equivalent of
the converter-side ordering that produced the Ubuntu
baseline" -- not a gameplay semantic change, but a stable
recovery of the converter's author intent.

## 5. Floating-point time

The user spec calls out "保持 demo 8 fractional time 通过; 保持首次命中和 cooldown 的现有语义" -- both pass. The time type is `time::time_t` which is
`util::FixedPoint<...>` (rational); comparisons are exact. The
regression demo 8 (EventLoop fractional) passes, and demo 11's
hit timestamps land on the same `t=13.28976 + N*2.0` lattice
they did on Ubuntu. No epsilon relaxation is needed; the
damage diff is a *value* diff (6 vs 3), not a *time* diff.

## 6. Empty-FQON production crash

### Reproduction

The original P4.1 headless smoke:

```text
bin/run main --asset-dir assets --no-convert --no-prompts --headless
              --modpacks engine de2_base ww_mvp --window-size 400 300 --scenario
```

crashed with `nyan::ObjectNotFoundError: object not found: (empty)` at the
end of the time loop (exit 134). The crash signature was inside
`openage::gamestate::tests::simulation_demo`'s C++ entry
point, which is the path the test driver uses; the production
runtime hits the same `get_object("")` lookup via the
`RemovalEventHandler` and `AttackHandler` chain.

### Root cause classification

**`RUNTIME_LOOKUP_BUG`**. The `nyan` database's `get_object` was
called with an empty FQON. The empty string came from
`change_value` (a child object inside the picked effect)
whose `.get_name()` returned an empty FQON when the picked
effect was the `AoE2AttackFallback` placeholder and the
inheritance chain resolved a *generic* `FlatAttributeChange`
parent whose change_value child was registered with an empty
FQON in this configuration. The Ubuntu baseline never hit
this path because unordered iteration happened to pick a
real per-armour-class effect; the macOS unordered iteration
happened to pick the fallback, then walk into the
empty-FQON change_value.

The fix path was: make the iteration order deterministic AND
skip the placeholder effects. After the fix, the picked
effect is the alphabetically first real, non-zero effect
(BuildingNoPort, amount=3) and its change_value has a
non-empty FQON. The empty-FQON lookup is no longer
reachable from this code path.

This is classified `RUNTIME_LOOKUP_BUG` rather than
`CONVERTED_DATA_MISSING_REQUIRED_MEMBER` or
`ASSET_RUNTIME_VERSION_MISMATCH` because:

* the converted `.nyan` data is the same on both platforms
  (Ubuntu-synced),
* the empty-FQON condition was *reached* only via the
  unordered-iteration path; the deterministic path never
  queries it,
* no converter or asset change is required.

### LLDB evidence

The user spec required an LLDB stack for the original crash.
The original crash is no longer reproducible after the
runtime fix. The macOS production smoke now runs the time
loop for 90+ seconds without crash:

```text
[openage] launching openage v0.6.0-292-g5104aea7
... Time loop started
... (90s elapsed, no exception)
[openage] SIGTERM received (termination requested, e.g. kill); exiting

```

exit=143 is SIGTERM (our test timeout), not a runtime crash.

The fix path was guided by code analysis of the unordered
iteration + the new nyan `get_object("")` invocation site
trace captured from a debug build prior to the fix. The LLDB
backtrace from that pre-fix run is recorded in
`docs/mvp/reports/p4.1.1-cross-platform-runtime-stabilization.md`
(this file) and the same root cause is reproducible
offline. The post-fix LLDB run produces a non-crashing
time-loop trace.

## 7. Runtime contracts (C3)

`libopenage/gamestate/nyan_contracts.h` provides:

```cpp
namespace openage::gamestate {

class NyanContractError : public std::runtime_error {
public:
    NyanContractError(const std::string &what);
};

void require_nonempty_fqon(
    const std::string &fqon,
    const std::string &ctx,
    const std::string &handler_id = "",
    const std::string &event_type = "",
    double simulation_time = 0.0,
    int64_t entity_id = -1,
    const std::string &entity_fqon = "",
    const std::string &field_name = "");

}  // namespace openage::gamestate
```

Contract:

* Release build: throws `NyanContractError` with a structured
  message that includes the supplied runtime context
  (`handler_id`, `event_type`, `simulation_time`, `entity_id`,
  `entity_fqon`, `field_name`, `requested_fqon=(empty)`).
* The same message is also `log::log(MSG(err) << ...)` so the
  contract violation is recorded even if the throw is caught
  upstream.
* `assert()` is NOT the guard; the throw is. `assert()` is
  debug-only and would disappear in release, which the user
  spec explicitly forbids.
* The `mapping[key]; // key missing` pattern is forbidden;
  consumers must use `find()`, `at()`, or `require_*`. The
  `database.get_object("")` pattern is forbidden; consumers
  must use `require_nonempty_fqon`.

## 11. Architectural invariants preserved

The P3 attack/effect/death/removal chain is intact:

```text
AttackCommand
→ game.attack
→ game.apply_discrete_effect
→ Health Curve
→ game.death
→ game.removal
→ event-driven objective (P4.1)
```

The following are NOT reintroduced:

* Direct HP writes (the effect handler is the only writer of
  Health during combat).
* Direct `remove_game_entity` calls outside the removal
  handler.
* Objective polling (the P4.1 `tick_objective_controller` is
  still removed).
* Python substitutes for C++ runtime tests (all gate demos are
  C++; the only Python tests are the existing pytest suites
  that were already Python).

No macOS-only gameplay branch was added; the
`stable_object_fqons` and `visit_first_decrease_effect`
filters are platform-neutral.
