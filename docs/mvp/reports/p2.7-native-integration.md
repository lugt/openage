## P2.7.1 — Native Mission Pack reader

Adds `libopenage/util/json_minimal.{h,cpp}` (minimal JSON parser, no
third-party deps) and `libopenage/scenario/mission_pack.{h,cpp}` (typed
MissionPack struct + `read_mission_pack(dir)` + `validate_mission_pack`).

Validation enforces:

- dense `terrain_ids_count == width*height`
- dense `elevation_count == width*height`
- chunk coverage: every tile belongs to exactly one chunk
- unique `scenario_object_id`, `trigger_id`, `player_id`
- non-empty `entity_definition_fqon`, position in bounds, owner is a
  defined player
- supported condition / effect kinds (per spec §7); unsupported kinds
  raise `MissionPackError` rather than being silently dropped
  (spec §10.1)
- trigger cross-references resolve
- victory kind is non-empty

Commit: `1e764d6b scenario: add native mission-pack reader`.

## P2.7.2 — Load Mission Pack into production GameState

Adds `libopenage/scenario/mission_pack_loader.{h,cpp}` and wires the
loader into:

- `Game::Game` — accepts an optional `mission_pack_dir`. When non-empty,
  `Game::load_scenario` reads the Mission Pack and calls
  `load_mission_pack_into_game_state`. When empty, the legacy nyan path
  runs (and warns).
- `GameSimulation::initialize` — derives `mission_pack_dir` from the
  scenario FQON by replacing dots with slashes
  (`ww_mvp.campaign.william_wallace.mission_01.Mission` ->
  `<assets/converted>/ww_mvp/campaign/william_wallace/`).
- `EntityFactory::add_player` — tolerates an empty `PlayerSetup` FQON
  (returns an observer-only player). The Mission 1 reconstruction uses
  this for the EnemyVillager's owner whose PlayerSetup is not yet
  modelled in the IR.

The loader follows the spec §6.3 order: terrain → players → diplomacy →
placements → object mapping → areas → triggers → initial events.

`ScenarioObjectId → GameEntityId` is registered explicitly via
`GameState::register_named_entity`, called with BOTH the computed full
PlacedEntity instance FQON (what the openage `objective_controller`
resolves) and the short `scenario_object_id` (what the
`openage.scenario` IR exposes). GameEntityIds are assigned in
placement-list order (monotonically increasing via
`EntityFactory::get_next_entity_id`), matching the
`openage.scenario.loader`'s contract.

Commit: `be5f47f3 scenario: load Mission Pack into production GameState`.

## P2.7.3 — Mission Pack emits chunk boundaries

`openage/scenario/writer.py` now writes `MapDefinition.chunks` (a list
of `{offset: {x, y}, size: {x, y}, tile_fqons: [...]}`). The 8x8 grid
matches the libopenage terrain_chunk API; edge chunks at the right /
bottom borders are NOT padded with bogus FQONs. The committed P1 dump
files in `docs/mvp/reports/mission1-scenario-dump/` are regenerated
from the canonical IR so the P1.4 golden tests stay green.

Commit: `02f5467c scenario: emit chunk boundaries in Mission Pack`.

## P2.7.5 — C++ integration test (demo 9) + headless smoke

Adds `libopenage/gamestate/demo/ww_mission1_native_load.{h,cpp}` (demo 9).

Run via `bin/run test --demo gamestate.tests.simulation_demo 9`. The demo
reads the Mission Pack and asserts:

- map 16x16 (width × height checksum)
- terrain/elevation checksum (256 == 16*16)
- 4 chunks (2x2 grid for 16x16 / 8x8)
- player IDs exactly {0, 1}
- 3 placements with correct FQON, owner, position
- invalid FQON surfaces (loader FQON resolution failure, not silent)
- duplicate `scenario_object_id` rejected by the reader's validator
- unsupported trigger kind is reported (spec §10.1)
- source-parser freedom: only `openage.scenario.*` and
  `openage.gamestate.*` headers, no `openage.convert.*` symbols, no
  SCX/SCN parser, no DE2 dat reader

Commit: `7d8d1ade test: verify native Mission Pack integration`.

## P2.7 known limitations (NOT blockers, deferred per spec §5.2)

- `PlayerDefinition.player_setup_fqon` is empty in the IR. The Mission 1
  reconstruction uses `EntityFactory::add_player`'s new empty-FQON
  tolerance for the EnemyVillager's owner (player 1). P5 will wire the
  FQON back in once `openage.scenario.ir.PlayerDefinition` exposes it.
- Triggers are loaded as definitions only; execution is P4 work.
- Areas are loaded as definitions only; dependency watchers are P4
  work.
- Diplomacy is an empty matrix; extension point is
  `MissionPackLoadError::load_mission_pack_into_game_state` step 3.

These do NOT affect the Mission 1 MVP end-to-end flow (demo 7 / 8 / 9
all pass through the new loader).
