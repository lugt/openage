# P4.4B — Footprint + Placement Validation

## 0. Scope

Mission 1 entities now have explicit gameplay footprints; placements
are validated at load time; the static occupancy grid is the
single source of truth for "is this tile walkable for a static
entity?" -- consumed by P4.4C's A*. The existing flow-field
pathfinder is **not** modified; the detour throw it exhibits is
deferred to P4.4C.

## 2. Coord / bound semantics (locked)

- placement position = **center** anchor.
- bounds = `[cx - rx, cx + rx) x [cy - ry, cy + ry)` (half-open).
- **1 cell = 1 tile**; cell anchor = **cell center**.
- covered rule: cell is blocked iff its center lies inside the bounds.
- TC rx=2.0 world = 2 tiles half-extent = 4x4 tile footprint.
  At placement (8,8): cells `(6,6)..(9,9)` (centers 6.5..9.5 in bounds).
- Villager rx=0.2 world = 0.2 tiles half-extent. Under
  cell-center containment, the bounds `[3.8,4.2)x[7.8,8.2)` contain
  no cell center -> 0 cells covered. This is the spec contract
  ("do not permanently write moving units to the static grid").
  A larger unit (rx >= 0.5) covers its center cell.

## 3. Data source hierarchy (per spec IV)

1. nyan `Collision.hitbox` (radius_x, radius_y) -> Footprint
2. Mission Pack override (TODO: reserved for future spikes; the
   production dump uses the nyan Collision data directly)
3. reconstruction fallback (handled by the factory's defensive
   nyan read)
4. required data error: the PlacementValidator's
   `INVALID_FOOTPRINT` + `STATIC_OBSTACLE` reason distinguishes
   missing-Collision from genuine overlap.

EntityFactory and the PlacementValidator do **not** key on the
specific FQON of TownCenter or Villager; the Footprint is keyed
on the Collision ability, which the converter emits uniformly
across entities.

## 4. Footprint data structure

`openage::gamestate::component::Footprint` is a **plain data
class** (not an `openage::Component`). Rationale: the Component
base is non-copyable (BaseCurve's copy is explicitly deleted) and
has no default constructor; pure geometry data is a poor fit for
the event/curve infrastructure. The Footprint is stored on the
entity as a field (`entity->set_footprint`) and is read by the
PlacementValidator, the StaticOccupancyGrid, and the viewmodel.

```
struct FootprintBounds { double min_x, min_y, max_x, max_y; ... };
enum class FootprintShape { AXIS_ALIGNED_RECTANGLE };
class Footprint {
  FootprintShape shape;
  double radius_x, radius_y;  // tile half-extents
  bool blocks_placement, blocks_pathfinding, is_static;
  FootprintBounds bounds_;    // recomputed on set_center
  static Footprint make_rectangle(rx, ry, blocks_placement, blocks_pathfinding, is_static);
  void set_center(cx, cy);
  // setters: set_extents, set_blocks_placement, set_blocks_pathfinding, set_is_static
  // accessors: shape, radius_x/y, blocks_*, bounds(), overlaps(...)
};
```

Footprint is copyable / movable / default-constructible (validator
and grid both copy FootprintBounds by value).

## 5. StaticOccupancyGrid + NavigationGrid

```
class StaticOccupancyGrid {
  bool is_blocked(CellPosition) const;        // out-of-map = blocked
  std::optional<entity_id_t> blocker_of(CellPosition) const;
  std::optional<entity_id_t> occupy(entity, FootprintBounds);  // reject overlap
  void release(entity);
};
```

`NavigationGrid` (P4.4C contract) is an abstract interface:
`is_walkable(cell)`, `cost(cell)`. `TerrainNavigationGrid`
composes terrain walkability (P2 APITerrain) and the
StaticOccupancyGrid; P4.4C's A* consumes it.

## 6. PlacementValidator

```
enum class PlacementFailureReason { OK, OUT_OF_MAP, UNWALKABLE_TERRAIN,
  STATIC_OBSTACLE, ENTITY_OVERLAP, INVALID_FOOTPRINT };
struct PlacementFailure { reason, blocking_entity, requested_bounds, context };
struct PlacementRequest { entity, entity_fqon, scenario_object_id,
  center_x, center_y, radius_x, radius_y, blocks_placement };
class PlacementValidator {
  PlacementFailure validate(req) const;
  PlacementFailure validate_and_occupy(req);  // on success, occupies the grid
  std::optional<pair<cx,cy>> find_nearest_valid(req, max_radius) const;  // debug only
};
```

Production policy = **fail loud**: `validate_and_occupy` on failure
returns the `PlacementFailure` and the loader throws
`MissionPackLoadError` with the reason + FQON + ScenarioObjectId
+ context. The debug `find_nearest_valid` is gated by `max_radius`
and uses a stable row-major ring scan; it is not used in the
production load path.

## 7. Mission 1 fixtures

- **direct_combat (production)**: Villager (6,4), TownCenter (8,8),
  Enemy (10,4). The TownCenter footprint blocks cells (6,6)..(9,9);
  the Villager (rx=0.2, sub-tile) and Enemy occupy their center
  cells, both outside the TC. The straight attack line y=4 from
  x=6 to x=10 does not cross the TC footprint, so the existing
  flow-field pathfinder's attack-chain path succeeds (no detour).
  demo 7 / demo 20 (data-driven victory) work end-to-end with
  this layout.

- **tc_obstacle (test fixture)**: Villager (2,8), TownCenter (8,8),
  Enemy (12,8). The straight line from (2,8) to (12,8) crosses
  the TC's (6,6)..(9,9) footprint cells. demo 27 pin 7 asserts
  that this line traverses blocked cells. Until P4.4C, the
  flow-field pathfinder ignores the grid and walks straight
  through; the **structural proof** that TC blocks the line is
  in the grid (verifiable without a working A*). P4.4C will
  consume the grid and route around.

## 9. Architectural invariants preserved

- Collision data source is the nyan ability; no FQON hardcoding
  in the pathfinder (pathfinder is unmodified).
- Renderer and selection bounds (sprite-based) remain separate
  from gameplay footprint.
- The existing flow-field pathfinder is untouched; the detour
  throw is documented and deferred to P4.4C.
- Placement validation is fail-loud; the debug relocate policy
  is opt-in and bounded.

## 10. Runtime contracts (per spec X)

- Footprint half-extents are finite, >= 0 (clamped).
- Placement positions are finite (tile coords).
- Entity FQONs are non-empty (loader passes the production FQON
  to the PlacementFailure context).
- Occupancy is idempotent for the same entity; rejects overlap
  with a different entity with a clear `blocking_entity` id.
- Missing Collision ability is non-fatal (entity is footprintless);
  the validator catches the missing-footprint case as
  `STATIC_OBSTACLE` (the center-cell query reports a default
  zero-extent footprint as 0 cells, so an entity with a missing
  Collision can still be validated -- it just doesn't block).
  `INVALID_FOOTPRINT` triggers only for negative or non-finite
  extents.
- Mission Pack load errors always carry context (entity FQON,
  ScenarioObjectId, position, reason).

## 11. P4.4C entry point

P4.4C's A* consumes the same `NavigationGrid` (P4.4B provides
the `TerrainNavigationGrid` implementation). The Move runtime's
pathfinder query call site can be redirected from the current
flow-field pathfinder to the A* pathfinder without touching the
Move component or the Attack system. The
`StaticOccupancyGrid` instance is currently local to the loader
load; the A* needs it persisted to the GameState. That move is
P4.4C's first step.

The minimum P4.4C surface:
```
class NavigationGrid {  // already declared
  virtual bool is_walkable(CellPosition) const = 0;
  virtual double cost(CellPosition) const = 0;
};
class AStarPathfinder {
  AStarPathfinder(NavigationGrid& grid);
  std::vector<coord::phys3> find_path(coord::phys3 start, coord::phys3 target) const;
};
```

The A* reads `is_walkable` and `cost` from the grid; the Move
runtime's `find_path` is replaced by a thin wrapper that
constructs the start/target cells from phys3 positions and
returns a list of waypoints for the existing Move system to
follow via Position Curve (P4.4C preserves the curve-based
continuous motion).
