# Testscene nyan fixtures + stopgap schemas (MVP)

This directory is the **tracked source of truth** for the hand-written nyan data
that the William Wallace Mission 1 MVP scenario needs for its terrain. These
files are **not** converter products and **not** generated by
`convert-export-api` (api_export). They are a hand-authored stopgap so the
testscene terrain (`TestsceneGrass`, 16×16 map) can load.

## Why this exists

The `engine` modpack under `assets/converted/engine/` is `.gitignore`d (it is
regarded as generated/copyrighted asset output). The MVP scenario, however,
needs a hand-written terrain fixture (`testscene_data.nyan`) and three
hand-written stopgap schemas that cannot be regenerated by the converter or
api_export. Without tracking them, a clean checkout cannot reproduce the
scenario terrain - it would depend on machine-local ignored files. This
directory fixes that by keeping the hand-written files in a tracked location
and providing an install step that copies them into the runtime location.

## The files

### Fixture (terrain data, hand-written)

| Source                          | Runtime (`assets/converted/engine/test/`)   |
|---------------------------------|---------------------------------------------|
| `fixtures/testscene_data.nyan`  | `testscene_data.nyan`                       |

`testscene_data.nyan` defines `TestsceneGrass` (and the supporting terrain
type, graphic, sound, animations, abilities, and `TestsceneVillager` /
`TestsceneTownCenter` / `TestsceneEnemyVillager` game entities retained as a
test fallback). The Mission 1 scenario (`mission_01.nyan`) references
`engine.test.testscene_data.TestsceneGrass` for all 256 terrain tiles.

### Stopgap schemas (hand-authored additions that api_export does not emit)

| Source                       | Runtime (`assets/converted/engine/util/`) | Adds                                                                  |
|------------------------------|-------------------------------------------|-----------------------------------------------------------------------|
| `schemas/game_entity.nyan`   | `game_entity.nyan`                        | `PlacedEntity` (entity + tile position, used by `Scenario.initial_entities`) |
| `schemas/scenario.nyan`      | `scenario.nyan`                           | `Scenario` class (`size`, `terrain_chunks`, `initial_entities`) - api_export does not emit this file at all |
| `schemas/terrain.nyan`       | `terrain.nyan`                            | `Size` (x/y) and `TerrainChunkLayout` (offset/size/tile_fqons)        |

`game_entity.nyan` and `terrain.nyan` are emitted by api_export **without** the
stopgap classes; `install.sh` overlays the hand-written versions on top of the
generated base. `scenario.nyan` is entirely hand-written (api_export does not
emit it). These three keep their `engine.util.*` FQONs because
`mission_01.nyan` imports them as `engine.util.game_entity` /
`engine.util.scenario` / `engine.util.terrain`.

## Where the Mission 1 scenario lives

The Mission 1 scenario object (`Mission`) and its `PlayerSetup` live in the
**ww_mvp modpack**, not here:

- Tracked source: `assets/nyan/ww_mvp/campaign/william_wallace/mission_01.nyan`
- Installed by: `assets/nyan/ww_mvp/install.sh` -> `assets/converted/ww_mvp/`
- FQON: `ww_mvp.campaign.william_wallace.mission_01.Mission`

That scenario imports `engine.test.testscene_data` (terrain) and real `de2_base`
game entities (`villager`, `town_center`) for the initial placements.

## Reproduce the scenario on a clean checkout

```bash
# 1. Build the engine (see repo build docs).

# 2. Generate the base engine schemas (the api_export nyan files).
python -m openage convert-export-api assets/converted

# 3. Overlay the 3 stopgap schemas and add the testscene terrain fixture.
bash assets/test/nyan/testscene/install.sh

# 4. Install the ww_mvp modpack (Mission 1 scenario + PlayerSetup).
bash assets/nyan/ww_mvp/install.sh

# 5. (optional) sanity-check that the scenario loads.
bash assets/test/nyan/testscene/validate.sh

# 6. Run the scenario.
bin/run --scenario --no-prompts
```

## Validate

`validate.sh` runs `bin/run --scenario --headless --no-prompts`, confirms the
log shows

```
load_scenario: ww_mvp.campaign.william_wallace.mission_01.Mission size=16x16 chunks=4
load_scenario: ww_mvp.campaign.william_wallace.mission_01.Mission initial_entities=3
```

and that no nyan `LangError`/`NameError`/`MemberNotFoundError`/... appears.

## Scope and known limitations

- These are a **Phase 0 stopgap**. The proper long-term solution is to teach
  `api_export` (or the converter) to emit `PlacedEntity`, `Scenario`,
  `TerrainChunkLayout`, and `Size` as first-class engine schema, and to source
  the terrain + scenario from a real campaign/scenario pipeline. That is
  out of MVP scope (do not modify the converter here).
- `install.sh` overlays the stopgap `game_entity.nyan` / `terrain.nyan` over
  the api_export output. If a future api_export changes the base content of
  those two files, the overlay here must be re-derived (re-apply the stopgap
  additions onto the new base).
- `validate.sh` proves the scenario loads headless (3 entities spawn, no nyan
  errors, survives the timeout window). Selection / movement / combat still
  require manual verification at the display with `bin/run --scenario`.
